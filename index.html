Frequently Asked Viva Questions & Answers

Q1

Why use a Min-Heap instead of simply sorting an array for smart recommendation?

Answer: Sorting an entire array takes O(n log n) time. With a Min-Heap, we can build or insert candidate slots in O(k log k) and extract the single best slot in O(1) peek or O(log k) extractMin. When slot availability dynamically updates, inserting a newly freed slot into an existing heap takes only O(log k) without re-sorting the whole lot.

Q2

Why is BFS preferred over DFS for finding reachable parking slots?

Answer: Breadth-First Search (BFS) explores all neighboring nodes at distance 1 before moving to distance 2. In an unweighted graph representing parking zones, BFS guarantees finding the nearest reachable available slot with the minimum number of edge hops from the entrance. DFS might traverse deep into remote dead-ends before backtracking.

Q3

How does the custom Hash Map handle collisions?

Answer: Our implementation uses a polynomial rolling hash function modulo bucket size: hash(key) % capacity. For collisions (two different license plates mapping to the same bucket index), we implement Separate Chaining using linked entries within that bucket. This maintains average O(1) retrieval.

Q4

What happens algorithmically when a vehicle exits and the waiting queue is not empty?

Answer: An automatic atomic handoff occurs: 1. The exiting car is unlinked from the LinkedList and deleted from the HashMap. 2. Its slot is marked available in the Array. 3. If waitingQueue.isEmpty() == false, we call waitingQueue.dequeue(). 4. The dequeued car is immediately allocated the newly freed slot (or routed via Min-Heap). 5. All structures (LinkedList, HashMap, Stack) are updated synchronously.

Q5

Why maintain both an Array and a Linked List for vehicles?

Answer: The Array represents physical, fixed infrastructure (the 24 physical bays that always exist). The Linked List represents dynamic occupancy (only active cars). If only 3 cars are parked, iterating through the Linked List visits only 3 nodes, whereas scanning the parking lot array requires checking all 24 slots.

Q6

How is the Priority Score in Min-Heap calculated?

Answer: The composite priority cost formula is: score = (distanceFromEntrance * 0.7) + (zonePreferencePenalty * 0.3) Lower score signifies higher priority (closer to entrance & matching driver's zone preference). The Min-Heap root always holds the element with the absolute lowest score.
